# Writing a Great PR Body ⭐⭐

A strong PR description turns a code dump into a conversation. It documents intent, guides reviewers, and can automatically close related issues when merged.

## Setup

This lesson is conceptual. No sandbox is required.

## Step-by-step task

1. Find a recently merged PR in a popular open-source project and read its description.
2. Identify which of these elements it contains:
   - Summary of changes
   - Linked issues
   - Testing instructions
   - Screenshots or GIFs
   - Checklist
   - Badges
3. Draft a PR body for a hypothetical bugfix that meets **all** of the following criteria:
   - Uses closing keywords to close issues #12 and #15.
   - Embeds a Codecov badge.
   - Includes a testing checklist with at least three items.
   - Is structured so that a squash-merge produces a clean commit message.

## ❓ Normal question

What elements make a good PR description?

## 🔥 Tricky question

Write a PR body that closes #12 and #15, embeds a Codecov badge, includes a testing checklist, and is set up for a clean squash-merge — then explain why the PR title (not the body) becomes the commit message on squash.

## ✅ How to check yourself

Your drafted PR body contains all required elements, and you can articulate the relationship between the PR title and the final squashed commit message.
