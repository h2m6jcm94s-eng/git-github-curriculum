# Forking a Repository ⭐

Forking is the gateway to open-source contributions. It creates your own copy of a project under your account so you can experiment, modify, and propose changes back via pull requests.

## Setup

This lesson is conceptual. No sandbox is required.

## Step-by-step task

1. Navigate to a public repository you do not own (e.g., `octocat/Spoon-Knife`).
2. Click the **Fork** button in the top-right corner.
3. Select your personal account as the destination.
4. Once the fork is ready, notice the URL now lives under your username.
5. On your fork's page, locate the **Sync fork** button and read its tooltip.
6. Think about when you would sync a fork versus when you would pull in your local clone.

## ❓ Normal question

What's the difference between a fork and a branch?

## 🔥 Tricky question

You forked a repo, the upstream added new commits. You sync via web UI but your local clone doesn't see them. Why?

## ✅ How to check yourself

You can clearly articulate the difference between a fork and a branch, and explain the two-step sync process (web UI + local `git pull`).
