# Create and Triage Issues ⭐

Issues are GitHub's native tracking tool for bugs, features, and tasks. Learning to write good issues and triage them efficiently keeps a project healthy and contributors happy.

## Setup

This lesson is conceptual. No sandbox is required.

## Step-by-step task

1. Open any active repository on GitHub and click the **Issues** tab.
2. Click **New issue**.
3. Write a clear title and description for a hypothetical bug (e.g., "Login button unresponsive on mobile").
4. Add a label such as `bug` or `good first issue`.
5. Use `@username` to mention a collaborator in the description.
6. Add a task list using `- [ ]` markdown syntax.
7. In a comment, type `Closes #12` to see how GitHub renders the link.
8. Explore the **Milestones** and **Assignees** sections.

## ❓ Normal question

How do you link a PR to an issue so merging closes it?

## 🔥 Tricky question

You wrote "Fixes #12" in a commit message on a feature branch. Will merging the PR close #12? What if you wrote it in the PR description instead?

## ✅ How to check yourself

You can list the linking keywords and explain where they must be placed to trigger automatic closing.
